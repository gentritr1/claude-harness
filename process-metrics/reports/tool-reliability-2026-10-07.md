## 0. Findings (hand-written 2026-10-07 from the data sections below; re-check numbers after any regeneration)

Owner question (2026-10-07): where do agents fail, loop, double-work or wait; is it the environment, the terminal or the
agent; which tools fail less; and what rules carry to every project. Tags: **[measured]** = computed by `harness-audit` from the
transcripts; **[inferred]** = reasoning on top of the data, not tested; **association** = correlation only.

**Data:** 1,629 transcript files (2026-06-24 .. 2026-10-07, 34 project keys). Forked and resumed sessions copy transcripts:
152 subagent copies, 3 main transcripts and 2,706 duplicate calls were removed, leaving **135,035 paired calls; 3,976
failures (2.9 %)**; 93.8 % of failures have a named cause, "other" + unexplained non-zero exits are 6.2 % (section 2).
[measured]

### Five-line answer
1. **The agent's waiting habits cost the most, not the host.** Foreground waits and long foreground commands that ran into their
   limit are the top two causes: 257 + 261 failures and **61.4 h** of the 82 h lost to failures. Of 269 non-wait timeouts, 8
   were later followed by a passing identical rerun; the number of reruns itself is not measured, so this bounds how often
   host load explained a timeout but is not a rerun pass rate. [measured]
2. **The §9 "never wait in the foreground" rule, written 2026-10-05, shows no detectable improvement in the pooled data
   (association; 2-day window).** Foreground waits that hit the 10-minute cap: 196 in 69,774 Bash calls before it (0.28 %),
   35 in 8,885 after it (0.39 %). Per project it differs: arrows-game 0.94 % → 0.48 % (129 of 13,717 → 13 of 2,706),
   geoguesser flat (0.30 % → 0.39 %, 42 → 16 waits, within count noise). Two days cannot separate a rule effect from task
   mix; the hook experiment (frozen baseline `fg-wait-baseline-2026-10-07`) is the test. [measured; association]
3. **The dedicated file tools fail less than their shell equivalents, and this holds within the same agent:** Read vs cat/sed,
   Edit vs sed -i or a script, Write vs heredoc, Monitor vs until-loops, background vs foreground long commands. The Grep and Glob
   tools were never called (0 of 135k calls), so no grep comparison is possible. [measured]
4. **zsh is the main terminal tax, and quoting fixes it, not `sh -c`.** 437 zsh-specific failures: `=`-word expansion 284,
   unquoted glob no-match 129, `$VAR` not word-split 15, other 9. Wrapping in `sh -c` showed no within-agent difference
   (OR 0.65 [0.41-1.04]). Compound commands fail twice as often as simple ones (OR 2.07 [1.88-2.28]) and cause 248 of the 298
   worktree-guard rejections. [measured]
5. **Running several projects at once raised latency but not failure rate.** The failure rate is 2.5-2.9 % at 1, 2, 3 and 4+
   active projects. Median Bash file-read latency rises from 0.08 s to 1.06 s, and Read from 0.02 s to 0.06 s. Concurrency is a
   condition to record, not a route to change (§10). [measured; association]

## Proposed §11 rules (DRAFT, not applied: owner decides)
Each rule gives its evidence, the expected saving and the risk. Hours are hours lost from section 4 or 5 over 2026-06-24 ..
2026-10-07 (3.5 months, all projects).

1. **Wait only in the background or via Monitor; ask the owner to enforce it with a hook.** A foreground `until`/`while`+`sleep`
   needs `run_in_background: true`, and the condition must match failure and a deadline.
   - Evidence: 257 foreground-wait timeouts, 39.0 h. Same-agent failure 23.3 % vs 1.6 % with Monitor (OR 0.06). 284 waits ended
     in timeout (64.7 h). No detectable improvement after §9 in pooled data (0.28 % → 0.39 % of Bash calls hit the cap; association, 2-day window; arrows-game 0.94 % → 0.48 %, geoguesser flat).
   - Expected saving: about 11 h/month of blocked agent time, mostly arrows-game and geoguesser.
   - Risk: a hook can block a legitimate bounded loop. Allow loops wrapped in `timeout ≤30`.
2. **Any command expected to run more than about 2 min (build, full test, capture, analysis over transcripts or images, adb
   series) runs in the background.**
   - Evidence: 261 non-wait timeouts, 22.4 h; 202 hit the limit; 8 were later followed by a passing identical rerun (rerun count not measured). Foreground long-category failure 6.8 %
     vs 0.3 % in background (OR 0.03).
   - Expected saving: about 6 h/month.
   - Risk: a background failure surfaces later. Pair it with rule 1's failure-matching wait.
3. **Every wait condition also matches failure and has a deadline.** Use `grep -qE "Ready|Error|FAILED"` or a PID check, plus
   `timeout`.
   - Evidence: background wait loops that never matched ran 60 min to 13 h (snaxx-tech 784.9 min, odd-hours 3 × 60 min).
   - Expected saving: an hour-scale stall each time.
   - Risk: none.
4. **zsh quoting.**
   - Quote any word starting with `=` (`echo "== x =="`).
   - Quote globs passed as arguments (`--include='*.ts'`).
   - Never run a command from an unquoted `$VAR` that holds arguments. Use a script file or an array.
   - Evidence: 284 + 129 + 15 + 9 = 437 zsh failures, about 1.4 h, mainly geoguesser and arrows-game. `sh -c` is not the fix
     (no within-agent difference).
   - Expected saving: about 120 failed turns/month.
   - Risk: none.
5. **Use Read/Edit/Write for files, not cat/sed/heredoc. Use Read with offset/limit for large files.**
   - Evidence: within-agent OR 0.23 (Read), 0.43 (Edit), 0.09 (Write), 0.35 (ranged Read). `sed -i` also exits 0 on a silent
     no-match.
   - Expected saving: about 400 fewer failed calls over the window; small in hours.
   - Risk: none. Shell is still right for pipelines and aggregates.
6. **Read before Edit/Write.** After "modified since read" or 2 "string not found" errors, re-Read the region before the next
   Edit.
   - Evidence: 120 edit-before-read (lucky-shelf 43), 29 stale reads, 45 not found; 197 edit fail → re-edit files (2.0 h); worst
     case 11 failed of 15 edits on one file.
   - Expected saving: about 2 h.
   - Risk: none.
7. **One simple command per Bash call, especially in a worktree agent.** No `cd` into the shared checkout, no multi-statement
   mutations, and absolute paths in the worktree.
   - Evidence: compound commands fail more within the same agent (OR 2.07). 298 worktree-guard rejections (248 compound,
     132 mutating, 71 `cd`; futurisma-race 199).
   - Expected saving: about 300 rejected turns.
   - Risk: more tool calls. Each is cheap (median 1.6 s).
8. **Loop breaker.** After 2 identical failures of the same call, stop. Read the error, form one hypothesis
   (superpowers:systematic-debugging) and change the input or the approach. Never send a third identical call.
   - Evidence: 41 identical-retry loops (3.7-10.0 h), 20 of them abandoned anyway; 46 failure streaks (9.2 h).
   - Expected saving: at least 3.7 h. **INFERRED:** the "2" threshold is not tested against a counterfactual.
   - Risk: it could cut off a retry that would have passed under host load, but only 8 of 269 non-wait timeouts were later followed by a passing identical rerun.
9. **Browser tools.**
   - Load the built-in-browser skill before the first browser call.
   - Call read_page or screenshot before ref or coordinate actions.
   - Wrap `javascript_tool` code in an async IIFE.
   - If the pane is hidden or stuck after 2 timeouts, front it or ask the owner. Do not retry it a third time.
   - Evidence: the browser tool has the highest failure rate of the high-volume tools (5.9 %, 17,561 calls). Preconditions 207,
     JS errors 262 (41 `await`/`return`), pane timeouts 233 (3.1 h). Transcripts that loaded the skill failed 3.7 % vs 6.1 %
     (association).
   - Expected saving: about 3 h and about 500 failed calls.
   - Risk: low.
10. **Dispatch hygiene.** Before dispatching, check this session's dispatch list and the ledger for an agent with the same brief
    that has finished or is still running. A repeat brief must say why it repeats (fix round, resume).
    - Evidence: 3 re-dispatches of finished work (1.55 h) and 5 duplicates of running agents. All 3 finished-work cases are from
      kik-home-redesign 2026-07-12.
    - Expected saving: small. **INFERRED / low n.** Its main value is avoiding a costly repeat.
    - Risk: none.
11. **Do not leave subagents parked.** The coordinator answers a parked subagent before dispatching new work. Every brief says
    what to do when blocked: hand back a partial report rather than wait.
    - Evidence: 134 parked agents, median 15 min, p90 107 min, 105.8 h capped.
    - Expected saving: wall-clock only; compute is unaffected. **INFERRED** that a hand-back rule shortens it.
    - Risk: more partial hand-backs to review.
12. **A condition is not a cause until a rerun says so.** Record concurrency and loadavg (§10 conditions). Do not blame host load
    for a failure unless the identical rerun passes. Treat concurrency as a latency condition when timing work.
    - Evidence: the failure rate is flat at 2.5-2.9 % across 1 to 4+ concurrent projects; of 269 non-wait timeouts, 8 were
      later followed by a passing identical rerun (rerun count not measured); fs-read latency is 13× at 4+ projects.
    - Expected saving: it stops misattributing BEHAVIOUR timeouts (61 h) to the host.
    - Risk: none.

**Rejected candidates (no evidence):**
- "Always use absolute paths": the file-not-found rate is the same (OR 0.92).
- "Wrap scripts in `sh -c`": no within-agent difference.
- "Use the Grep tool": the tool is not exposed (0 calls).
- Builds of an unchanged tree and repeated test runs: 9 and 12 cases, under 0.3 h, not worth a rule.
- Graphify was not re-tested: errors a code map could prevent (file-not-found, string-not-found) total under 2 h, which is no new
  reason (see the 2026-10-07 trial).

### Surprises
- Forked and resumed sessions copy whole subagent transcripts into the new session directory. Without dedupe, double dispatch
  looked 60× worse (178 vs 3) and calls were inflated by 2,706.
- Grep and Glob tools: 0 calls in 135k. Every "use Grep, not grep" rule is void on this setup.
- `find` in the agent shell is a function that wraps `bfs`. Project directory names in `~/.claude/projects` start with `-`, so
  `find <dir>` there fails with `bfs: error: Unknown argument`. This was observed live during this audit and is not counted:
  the command still exited 0.
- The worst single waste is not a failure at all: one subagent stayed parked on its coordinator for about 9.7 days (tondo).

### Open verification gaps
- Hours lost = call time + reaction gap (capped at 10 min). This is an estimate, not a counterfactual.
- Unchanged-tree builds and test reruns are inferred within one transcript. Edits by other agents are invisible.
- Error causes come from first-match regex: 6.1 % are residual, and the bucket assignment for `timeout:command` is a judgement
  backed by the rerun count.
- Ledger lines carry `null` for loadavg, disk, shared emulator, outcome (approved/changes known for very few) and route version.
  Transcripts do not contain them.

## 1. Method
- Source: every `*.jsonl` transcript under `~/.claude/projects/` (main sessions and `subagents/`), scope: all projects. Files are streamed line by line by `harness-audit` (`~/.claude/process-metrics/bin/`); only digests (tool name, category, timings, hashes, program names, redacted <=120-char error signatures) are kept. No prompt text, file content or command text is stored.
- A **call** is a `tool_use` block paired with its `tool_result` by id. Latency = result timestamp - use timestamp (ms resolution; includes permission/classifier latency). Background Bash calls are excluded from latency and hours (their launch returns at once).
- **Failure** = `is_error` on the result, or a timeout (timeout text, `timedOutAfterMs`, or a foreground command "moved to the background" at its limit). Each failure gets one cause class from the result text (first match wins; rules in `harness_core.classify_error`) and one bucket: **ENV** (host, shell setup, sandbox, permissions, services), **TOOL** (a different tool or shell form avoids it), **BEHAVIOUR** (the agent's own step was wrong), **SIGNAL** (the command worked and reported a real failure: failing test, tsc error, grep no-match).
- **Hours lost** per failure = failed call time + the reaction gap to the agent's next tool call, capped at 600 s (longer gaps are dormancy or owner time). It is an estimate of the turn spent on the failure, not a measured counterfactual.
- `permission:user-rejected` latency is the owner's decision time, so it is excluded from hours lost (30.3 h of owner time).
- Timeouts of a command whose identical skeleton later succeeded in the same agent are re-labelled `timeout:host-load-passed-on-rerun` (8 calls).
- Tool-choice comparisons report raw rates with Wilson 95% CIs and a **within-agent** Mantel-Haenszel odds ratio (strata = agents that used both arms), which removes between-task mix but not within-task mix. A difference "counts" only when the within-agent CI excludes 1.
- Concurrency: a minute is active for a project when any of its transcripts has an assistant/user record in it. Associations only.
