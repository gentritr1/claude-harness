Decisions taken on 2026-08-22 (branch `refactor/modular-frontend`):
- Theme palette is declared ONCE on `body[data-theme]` as `--theme-*` tokens in `styles/themes.css`; machine, Signal Lab, speed picker and guide previews all consume them. Before this, the same palette was copy-pasted three times (`--machine-*`, `--lab-*`, `.speed-picker[data-theme]`).
- First-run onboarding is a native `<dialog>` ("guide"), not an inline card above the machine. Three steps kept (hear → path → machine) with copy cut to a title + controls per step.
- Coach strip and `MODE_GUIDANCE` removed: guidance lives only in the guide's path picker and the machine's status/answer-hint lines.
- Signal Lab headlines capped at 1.5 rem so the machine stays the visual center of gravity (product principle: "make the signal the strongest element").
- Themes' palettes/fonts were intentionally NOT changed — user asked to keep them and only polish.

**Why:** The user asked for fewer things, better structure, one design taste; the pass was implemented by a delegated Opus agent from a written brief, reviewed with before/after headless-Chrome screenshots.
**How to apply:** When adding a themed surface, consume `--theme-*`; do not reintroduce per-surface token copies. Keep guidance copy to one line per control. Related: [[verification-recipe]].

**Pass 3 verification gaps (2026-08-22, closed or stated):**
- Every acceptance criterion in brief 3 verified by CDP script except one: §6's "all of it sits within the middle 60 % of the stage" at 1280×800. Measured against `.practice-stage`, the centred group (status→keys) occupies **69.5 % terminal / 77.3 % teletext / 69.2 % pocket**, symmetric about the centre. It cannot be met while §6 also mandates `gap: var(--space-5)` between the five parts — the group would need ~54 px removed, which only comes out of the signal (against "make the signal the strongest element"). Reported, not approximated.
- `pickRound`'s rule 2 (review a stale mastered letter) fires for every mastered letter at the start of a fresh session because the per-session `seenRound` map is empty, so rounds 1–N are reviews and the first group round lands at round 8 rather than 4. Acceptable ("by round 8"), but worth knowing before tuning the policy.
- Group rounds record per-character hit/miss but deliberately **not** a response time: a five-letter word is copied as one act, so dividing its elapsed time per character would falsely promote letters to `Instant`.
- Test-harness scar: answering faster than the signal ends stores `responseMs` 0, and a median of 0 originally read as `Steady` rather than `Instant`. Fixed by branching on `responseMs.length` instead of truthiness — a "0 means no data" conflation.
- Test-harness scar: `Page.navigate` served **cached CSS**, so a real fix measured as unchanged. Always `Network.setCacheDisabled` in `scratchpad/cdp2.mjs` before trusting a layout number.
