Pattern → detection rule → brief/test update (CLAUDE.md §7), Morse Trainer, 2026-08-22:

- **Delegate's scripted test answered instantly; realistic timing hit a different policy path.** Pass 3's `pickRound` starved M (served K on rounds 3–10) only when answers came ~750 ms after the signal ended, because K became "mastered" and `dueLetters` treated a missing `seenRound` as infinitely overdue. → Reviewer reruns the core loop with *human-like timing*, not the delegate's fast loop. → Briefs for any selection/scheduling policy must include a pure **coverage assertion** (every item served ≥ N times over a session) and a reproduction with realistic timing.
- **"Dim placeholder" still encoded the answer.** Pass 3 kept real dot/dash widths on the pre-answer marks, so the pattern was readable while listening. → For any "hidden while deciding" requirement, the acceptance test measures the *rendered geometry* (computed widths equal), not the class name or opacity. → Brief 4 §1 + criterion 2.
- **Headless Chrome at 390 px clips the right edge** — not overflow. → Mobile truth = in-app browser / CDP emulation + `scrollWidth` (see [[verification-recipe]]).
- **Agent measured layout in one stage state only** (Learn round) while the intro card overflowed by 28 px. → Layout criteria must enumerate every stage state (round, intro, session end, sprint, send, settings open).

**Why:** Each of these reached review because the brief's acceptance test exercised the happy path the implementer chose, not the failing path.
**How to apply:** Before APPROVE, rerun the original scenario with realistic inputs and measure rendered/computed values; write the next brief's acceptance so that the same class of bug cannot pass. Related: [[design-pass-2026-08]].

Added 2026-08-22 (pass 4 implementation):
- **A state that exists only during a transient window was never rendered.** `state.playing` was set inside `playCurrentSignal` with no `context.render()`, so the "real marks during playback" state never reached the DOM — every static check passed. → Detection rule: for any state whose lifetime is a playback/animation window, sample the computed geometry *continuously* and pick the frame by timestamp; never assert it from a single post-hoc read. → Any brief that says "during X" must name the sampling method.
- **Harness scar: end-of-playback detection by a quiet window is wrong for Farnsworth text.** A 150 ms silence threshold fired on the ~680 ms inter-character gap of `MARK`, so "200 ms after playback ends" was measured mid-word and the marks looked leaked. → Sample into a buffer for the whole round and derive the true end as the last lit frame.
- **Harness scar: `?guide=off` skips the flow that plays round 1.** With the dev param the first round never auto-plays, so a scripted repro pressed Space, which counts as a replay and silently costs one first-listen attempt — the unlock then landed a round late. → Reproductions of first-visit behaviour must run the real guide, not `guide=off`.
- **Pre-fix confirmation without a pre-fix commit:** copied the tree to a scratch dir, restored only the old policy functions, served it on a second port, and ran the same script against both. Pre-fix: K served 9 of 12 rounds, M 3, no unlock. Post-fix: 5/5, intro for R at round 11, three runs in a row.
- **Headless Chrome measured layout with fallback fonts.** Pass 4 reported every stage state at 800 px; with Archivo/DM Mono/VT323 actually loaded the intro card was 865 px. → Layout acceptance must state `document.fonts.status === "loaded"` next to each number and run in a browser that fetches Google Fonts. → Brief 5 §12.
- **Probing the wrong element.** In the terminal theme `#signalBars` is `display:none` (glyph row `.signal-text` is used), so a width probe on it reads 0 and looks like a bug. → Probe the element the theme actually renders; check `display` before trusting a 0.
- **Brief example contradicted the rule it illustrated** (pass 5 §7: the retention example counted one 24 h anchor twice). The delegate chose the rule over the example and said so — correct. → When an acceptance example and a cited rule can't both hold, the reviewer must decide explicitly; don't mark the delegate down for refusing a wrong example.
- **Stage-swap transient overflow** (pass 5 §12 root cause): `display … allow-discrete` without `opacity: 0` on the hidden state leaves the outgoing block rendered *and* in flow during the swap. → For any card/stage swap, sample `scrollHeight` every animation frame across the transition, with web fonts loaded.
- **Hidden preview pane = every trial "interrupted".** The interrupted-trial rule keys off `document.hidden`; the in-app Browser pane reports hidden when collapsed (one tool call even said "The Browser pane is currently hidden"). → Live scoring checks must assert `document.visibilityState === "visible"` first, or the app looks inert and evidence is silently discarded.

Added 2026-08-23 (pass 9 implementation):
- **The machine has zero vertical slack at 1280×800, in every theme.** Adding a drawer section (the transmission archive) pushed `scrollHeight` 800 → 980. A fixed `max-height` cap on the drawer's scroll region fixed terminal but *grew* teletext (its ten rows are 318 px, not 336, so the cap became the floor). → Detection rule: any drawer/column addition must be measured in all three faces with the block toggled `hidden` on and off, and a per-theme delta reported. → The only cost-free pattern is taking the new block out of flow (`position: absolute; top: 100%` inside a `position: relative; overflow-y: auto` parent) so it contributes to scrollable overflow but not to intrinsic height.
- **Audio spies must be reset before the round is scheduled, not at the top of the test loop.** The next round is scheduled during the previous round's auto-advance, so `reset()` at the top of the loop erased exactly what was being measured and every round read "0 nodes". → Reset immediately after answering; read the spy at the top of the next iteration.
- **Brief 9's catalog annotations were wrong about spellability** (`SOS` marked as needing `KMRS`; `O` is the 7th Koch character). → A brief that pins data to a derived constraint must name the script that checks it; pass 9's `spellable()` + a printed per-entry assertion caught it before the data shipped.
- **Synthetic key events on `document` hid a dead keyboard for five passes.** Every review dispatched `document.dispatchEvent(new KeyboardEvent(...))`, which bypasses focus; real keys go to `document.activeElement` and bubble. `handleKeydown` bails on `event.target.closest("button")`, and focus sits on a button almost always (after the guide, after clicking Replay/an answer key, after every card), so real typing did nothing — found by the user playing, 2026-08-23. → Keyboard acceptance must use CDP `Input.dispatchKeyEvent` and must enumerate the **focus owner** per case, never just "press a key".
- **`[tabindex]:focus-visible` painted a 3 px ring around the whole machine.** Chrome moves focus to the nearest focusable ancestor when the focused element is hidden, so dismissing a card with Enter focused `#machine[tabindex="-1"]` with keyboard modality. → Never let programmatic scroll/focus containers match the widget focus-ring rule.

Added 2026-08-23 (pass 11 implementation):
- **Real vs synthetic keys, measured side by side on the same pre-fix build.** With `#replayButton` focused, CDP `Input.dispatchKeyEvent` reported `registered:false` (typed stayed `_`, `attempts` unchanged) while `document.dispatchEvent(new KeyboardEvent(...))` on the same build reported `registered:true`. → A keyboard acceptance that cannot tell those two apart is not an acceptance. Keep `scratchpad/keys11.mjs` (`press`/`focusOn`/`activeElement`) as the standing harness.
- **Scoping a focus-ring rule is only half the fix.** Changing `[tabindex]:focus-visible` to `[tabindex]:not([tabindex="-1"]):focus-visible` removed the 3 px teal ring but let Chrome's own `:focus-visible` ring through — `outline-style: auto`, 1 px, `rgb(153,200,255)` on `#trainer`/`#machine`/`#letters`. → Whenever an author outline is removed from something that still takes focus, add `outline: none` explicitly and assert `getComputedStyle(el).outlineStyle === "none"`, not just "our rule no longer matches".
- **Headless Chrome wedges (browser process ~90–110 % CPU, `/json/list` dead) after roughly 15–20 s of sustained round driving.** Reproduced identically with this pass's diff fully reverted to HEAD, so it is environmental, not a product regression. Not fixed by `--enable-unsafe-swiftshader`, by emulating `prefers-reduced-motion: reduce`, or by slowing the CDP poll loop. → Working practice: one fresh browser per script (`scratchpad/run11.sh`), and keep each script under ~20 rounds; long acceptance runs must be split.
- **`--headless=new` binds DevTools to 127.0.0.1 or `[::1]` non-deterministically between launches.** A client hard-coded to one family fails with `ECONNREFUSED` and looks like "Chrome did not start". → `scratchpad/cdp11.mjs` tries both.

Added 2026-08-23 (pass 12 implementation, app bar):
- **`color-mix(in oklch, …)` between two distant hues walks the hue wheel and lands on a third colour.** Brief 12 §2 prescribed `color-mix(in oklch, var(--theme-accent) 22%, var(--shell-surface))` for the active mode chip; amber (h 72) mixed with the shell surface (h 250) resolved to h 211 — sRGB 25,53,58, a dark **teal** chip, the exact colour the pass existed to remove. Same trap in the hover border: 50 % of amber with the shell border resolved to h 161 (green). → Detection rule: a `color-mix` between two hues is only safe in **oklab/srgb** (crosses the neutral axis) or against **`transparent`** (premultiplied — keeps the hue, halves alpha). Never trust a mix's hue from the formula; read the computed value and *look at the pixels*. Contrast maths would have passed all three variants (7.7–8.7:1) — only the screenshot showed it was the wrong colour.
- **A brief can prescribe a geometry that contradicts its own acceptance test.** §1 asked for a 44 px segmented box with a 3 px inset and 36 px inner buttons *and* for `getBoundingClientRect().top` to be identical for the box, each button and the Settings button. Those cannot both hold — an inset is exactly a difference of tops. → When an acceptance number contradicts the prescribed structure, implement the structure, report the real numbers, and say which clause you could not satisfy; the shared **centre line** (35.5 px in all three) is the check that actually expresses the intent.
- **Same-specificity overrides silently lost to file order.** `.mode-control { height }` placed *before* `.segmented-control { min-height }` was overridden; the box measured 44 but the buttons still rendered 44 and overflowed the inset, so the fix looked applied and was not. → Any "override the shared primitive" rule needs either higher specificity or a comment pinning its position, plus a computed-style read of the *overridden* property (padding 3px, radius 6px), not just the headline height.
- **`color-mix(in oklch, <accent>, <neutral>)` produced the exact colour the brief was removing** (amber→grey via the hue wheel = teal). The delegate caught it and kept side-by-side screenshots. → A brief that names a mixing space must say *why*; for accent-into-neutral use `oklab`, and acceptance should assert the resolved hue, not the formula.

Added 2026-08-23 (pass 13 implementation, one accent for the whole product):
- **A derived token declared in the same block as the palette gets shadowed by the local `[data-theme-tokens]` previews.** The machine preview tiles apply another machine's palette locally; anything that means "the ACTIVE machine's accent" must be declared on `<body>` (`:root, body[data-theme="x"] { --app-accent: var(--theme-accent) }`) so `var()` resolves once, at body, and inherits into the tiles as a plain colour. Put it in the shared `:root, body[…], [data-theme-tokens="…"]` block and a selected Teletext tile draws a *yellow* ring while the product is running Pocket. → Detection rule: for any "active theme" token, assert the value read from *inside a preview tile* equals the value read from `<body>`.
- **Chrome serialises a colour mid-transition as `oklab(...)` and at rest as `oklch(...)`.** A crossfade check comparing `getComputedStyle` strings reported "230 ms not at target" when the two strings were the same colour (oklch 0.84 0.14 72 ≡ oklab 0.84 0.0433 0.1331). → Crossfade/interpolation acceptance must compare **resolved sRGB bytes** (paint the value into a 1×1 canvas and `getImageData`), never serialised strings. Same helper doubles as the honest input to the WCAG formula. Standing harness: `scratchpad/probe13.mjs`.
- **`seedScript` (seed9.mjs) sets `morse-trainer-onboarding-complete`.** A "guide" acceptance seeded with it drives a **closed** dialog: every click handler still fires, every assertion still passes, and `#guide.open` is `false`. → Any guide test must assert `#guide.open === true` *and* `getBoundingClientRect().height > 0` before it measures anything. Add `localStorage.removeItem('morse-trainer-onboarding-complete')` after the seed.
- **The pocket LCD trap generalises to every light themed surface.** Deriving `--focus` from the accent fixed pocket (ring → `--lcd-ink`, 8.06:1) but left teletext's cyan `.machine-footer` at 1.15:1 for the Letters button at ≤ 900 px — and the *old* fixed teal ring measured 1.04:1 there, so it had never been visible. → Detection rule: audit **every rendered focusable control** in every theme at both widths against the first *painting ancestor* (the ring sits at 3 px offset, so the control's own background is irrelevant). Standing harness: `scratchpad/ring13.mjs`. Fix pattern: the light surface re-declares `--focus` as its own ink.
- **A `transition` declared in a losing `@layer` is a comment that never runs.** `.first-signal-pattern i { transition: … }` added in the `guide` layer is overridden by the same selector in `trainer` (layer order `foundation, guide, trainer, themes, …`). It read as done and did nothing. → Read the *computed* `transitionProperty`/`transitionDuration` off the element, not the rule you wrote.
- **Backticks inside a JS template literal that injects page code terminate the string.** `probe13.mjs` embedded prose with `` `.preview-screen` `` inside `export const PROBE = \`…\`` and node threw `ReferenceError: screen is not defined` from a *comment*. → Keep injected-page-code templates free of backticks.

Added 2026-08-24 (pass 15 implementation, Night Watch part 1):
- **A `python3` string-replace patch silently did nothing because the source contained U+00A0.** `KEYBOARD_HELP` in `trainer.js` separates its clauses with two non-breaking spaces; a patch anchored on `"Tap · dot   Hold · dash…"` typed with ordinary spaces matched nothing, so the new `watch:` entry was never added and the footer help rendered empty. `MODE_LABELS` on the same commit *did* apply, which made the diff look complete. → Detection rule: every scripted patch must assert its anchor (`assert old in s`) **and** the next command must grep the file for the new content. Never trust a `str.replace` that cannot fail loudly. Corollary: re-read the actual git diff for each intended change, not just the ones you happen to look at.
- **A repeat must not restart the window it was offered out of.** `openWindow()` began with `clearTimers()`, so the auto-repeat's own `openWindow` cancelled the pending "station closes down" timer and rescheduled it — the copy window silently became ~110 s instead of 67 s and the failure acceptance timed out looking like a hang. → Detection rule: any deadline that survives a sub-event must live outside the timer bag that sub-event clears; assert the *measured* elapsed time against the spec (26.1 s repeat at 62 % of 42 s, 67.3 s close-down at 1.6×), never just "the card appeared".
- **`waitFor` on a hidden element's `textContent` is not a state test.** The failure check polled `#watchCardTag.textContent === 'Unconfirmed'` while the card was `hidden`, so it read the stale brief tag forever and then reported the stale value as the result. → Always conjoin `!el.hidden` (or a rect check) with any text assertion.
- **Focusing a control on `requestAnimationFrame` after a synchronous render leaves a frame in which the key goes nowhere.** `beginSend` focused the paddle on rAF; a driver that started keying immediately sent Space to `document.body`, the trainer routed it to the word-gap handler, and zero marks were recorded — which then failed the send twice and ended the night, looking like a scoring bug. → Focus synchronously right after the render that unhides the control; in drivers, assert `document.activeElement` before sending input.
- **Headless pages cannot be hidden with `Emulation.setPageVisibilityOverride` (not in the protocol) and stay `visible` behind a new tab while focus emulation is on.** The working recipe for a real `visibilitychange` + `blur`: `Emulation.setFocusEmulationEnabled {enabled:false}` → `Target.createTarget` → `Target.activateTarget` on the new target; restore by activating the page target and re-enabling focus emulation. Standing harness: `scratchpad/nwvis15.mjs`.
- **A CDP paddle driver must emit the word gap after every word but the last.** `if (wordIndex) await sleep(520)` skips the gap after word 0, so `R AT MOONRISE` keyed `R`+`A` with no letter gap either and decoded as one unreadable symbol — reported as a product decode failure. → `if (wordIndex < words.length - 1)`.
- **Reusing an existing class inherits its theme overrides, including ones written for a different background.** `.intro-tag` is re-coloured to `--lcd-ink` on pocket because the pocket stage blocks are LCD glass; a new card that used `.intro-tag` without also being glass rendered dark ink on the dark machine surface. → Detection rule: when a new surface borrows a class, grep `themes.css` for that class *and* for the block it normally lives inside, and screenshot the borrowed state in all three machines.
- **Standing harness for this mode:** `scratchpad/run15.sh` (fresh headless Chrome per script, `--autoplay-policy=no-user-gesture-required` so the AudioContext runs), `scratchpad/nw15.mjs` (seeds whose *computed labels* are Stable/Steady, real-mouse `click`, `padPress`, `playNight1`), and an `AudioContext` factory wrapper installed via `Page.addScriptToEvaluateOnNewDocument` that records every `osc.start/stop`, `gain.connect` value and `filter.connect` — the only honest way to say "the noise bed is 0.015" rather than quoting the config.

- **Pass 15 (2026-08-24): a hidden card's flag swallowed the mode's documented key.** `setMode` cleared `introLetter`/`sessionDone` but not `contactOpen`/`arrivalOpen`; entering Night Watch past the returning-learner greeting left the invisible arrival card "open", and the keyboard handler's dismiss branches ate the first Enter (Watch's "Enter · send"). The agent's seeds never had a greeting pending, so its end-to-end run couldn't hit it. → Detection rule: **acceptance runs must seed the returning-learner greeted state** (sessions ≥ 1, last scored event ≥ idle gap) and verify every documented key from there; when a keyboard claim passes, also assert WHICH handler consumed the event (capture listener + defaultPrevented), not just the outcome.
