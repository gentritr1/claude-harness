**Browser-tool scar:** after resize_window, screenshot coordinate space silently flips between 1x and 2x — re-screenshot before every click. On mobile-emulated viewport (<768px), computer clicks time out after 30s but the tap often still lands; prefer read_page refs, and verify state by screenshot rather than trusting the click result. The computer key action injects KeyboardEvents with EMPTY `key` — Chrome never runs native button activation, so "pressed Enter, nothing happened" is instrument error, not evidence (this invalidated a pass-3 keyboard verdict; the honest probe is `.click()` for handler existence + a note that trusted-key activation follows from real `<button>` semantics). Instant DOM readback after `.click()` can false-negative when the game animates — wait, then re-read. Related: [[za-table-and-log]]
