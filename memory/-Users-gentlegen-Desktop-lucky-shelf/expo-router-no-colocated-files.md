**Scar (2026-07-11):** B-M9 co-located `X.styles.ts` + `X.styles.test.ts` next to each
route in `src/app/`. expo-router's `require.context` (see `expo-router/_ctx.*.js`) globs
EVERY `.ts/.tsx` under the app root as a route — the match pattern only excludes
`+api/+html/+middleware/+native-intent`, NOT `.styles.` or `.test.`. Result: the
`.styles.ts` files minted junk routes (`/catalog.styles`, `/run.styles`, …) and
`_layout.styles.ts` + `_layout.styles.test.ts` both mapped to the `/_layout.styles`
layout and made `getRoutes()` THROW "layouts conflict". That collapses
`.expo/types/router.d.ts` (gitignored, regenerated by expo) to the empty
`RelativePathString` fallback → `tsc` fails on every `router.push('/route')`, and it
pollutes/crashes the runtime route tree the same way.

**Why it hid:** B-M9's approval rested on vitest byte-identity, which never exercises the
expo-router route tree; and the app hasn't been run on-device since B-M9 (device pass =
open Gate-2 item). `router.d.ts` is gitignored, so a stale-but-valid pre-B-M9 copy kept
`tsc` green until something regenerated it.

**Fix:** moved all 20 files to `src/screen-styles/` (sibling OUTSIDE the router root),
route imports now `@/screen-styles/*`. Landed on BOTH branches: `a147e05`
(graduation-flip) and cherry-picked to `main` as `4d42bf4` (main green: tsc 0, 291/291,
fixtures valid, determinism pin intact). Same patch on both → dedupes at merge via
patch-id.

**Detection rule → future briefs/reviews:** any file added under `src/app/` MUST be a
route. Co-locating styles/tests/helpers there is banned. When reviewing UI-structure
work, run `getRoutes`/typed-routes (or `expo start`) — not just vitest — because unit
tests are blind to the route tree. To regenerate types headlessly:
`scripts`-style node script setting `EXPO_ROUTER_APP_ROOT=src/app` and calling
`@expo/router-server/build/typed-routes/generate`.`getTypedRoutesDeclarationFile(ctx)`.
