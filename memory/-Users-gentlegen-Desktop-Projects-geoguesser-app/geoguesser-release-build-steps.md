`./scripts/build-aab.sh` runs `gradlew bundleRelease` only — it does not install
anything. `node_modules` was absent on 2026-08-28 and the release build bundles
JS through Metro, so run `npm ci` first or the build fails.

The native project under `android/` is committed (not regenerated by prebuild),
so **`app.json` is not read at build time**. `versionCode` / `versionName` must
be bumped in BOTH `app.json` and `android/app/build.gradle` — gradle is the one
that actually lands in the artifact.

Released so far: 1.2.2 (7) on 2026-08-08; 1.3.0 (9) built 2026-08-28;
1.3.1 (10) built 2026-08-31, uploaded, committed only on 2026-09-07 as tag v1.3.1 (first build containing expo-haptics — a new
native module autolinks fine into the committed android/ project; confirm
with `strings base/dex/classes*.dex | grep expo/modules/<name>` on the AAB).
versionCode 8 was set on the branch but never shipped, so 9 was used to stay
safe against a possible manual upload of 8.

1.4.0 (11) built 2026-09-07 from `feat/v1.4-tester-feedback` (adds expo-store-review; check
`expo/modules/storereview` in the dex the same way).

1.5.0 (12) built 2026-09-18 from `main` at 305d2d7 (tag v1.5.0; main fast-forwarded to
feat/v1.4-tester-feedback + version bump — 1.4.0 plus the playerStore and world-fit map fixes, NO
next-level work). Clean build: `rm -rf android/app/build $TMPDIR/metro-cache`, `npm ci`, then
`env -u CI -u EXPO_PUBLIC_FORCE_TEST_ADS -u EXPO_PUBLIC_QA_PANEL ./scripts/build-aab.sh` (7 min).
Verified against ~/Desktop/geoguesser-1.4.0-11.aab: same package and upload-cert SHA-256, identical
permissions and ad-unit strings, the fix present in the bundle. Copied to
~/Desktop/geoguesser-1.5.0-12.aab (sha256 a748836d…). Main's line has no build stamp or release
guard (those live on feat/next-level), so the store switches are checked by hand.

Artifact check gotcha: `strings bundle | grep -c <publisher>` reported 0 real ad units in BOTH the
shipped 1.4.0 and the new AAB — grep -c counts lines and strings' line breaks split the Hermes string
table unpredictably. Search the raw bytes instead (python `bytes.count`, or `grep -c` on
`unzip -p <aab> base/assets/index.android.bundle | LC_ALL=C grep -ao 'ca-app-pub-[0-9]*/[0-9]*'`).
Returning to feat/next-level after a main-line build needs `npm ci` again (react-native-svg etc.).

**Why:** two of these (missing node_modules, app.json being inert) fail or
mislead silently.

**How to apply:** before a release build — `npm ci`, bump both files, then
verify the built artifact with `bundletool dump manifest --bundle <aab>` rather
than trusting config. See [[verify-webview-maps-without-a-device]] and
[[android-package-is-frozen]].
