Round-1 -> round-2 of the Fuseline concept loop (2026-07-18):

- **Pattern:** round-1 proposal had invented numbers (target curve, a share example off by
  3 orders of magnitude) and a name colliding with a shipped Steam game. **Detection rule:**
  recompute every worked example by hand; search every proposed name; demand each spec
  number name the script that produced it. **Brief update:** round-2 brief required the
  actual solver be written and run BEFORE the spec was accepted — this worked: the measured
  gate (M1/M2/M3) forced a real rules change (Static tile) the proposer would not have
  found by prose.
- Opus retracted 4 of its own round-1 claims once told numbers must be computed (including
  a spoiler leak in the share format I hadn't caught). Demanding computation produces
  honesty better than demanding honesty.
- Reviewer reproduction cost ~2 min (6 solver commands) because the brief required a
  dependency-free single-file harness with named modes. Keep requiring that shape.
- **Why:** this project's recurring cross-project scar (4x on Lucky Shelf) is numeric
  thresholds never computed from live data; the fix that finally worked is making the
  solver a concept-phase deliverable, not an implementation-phase one.
- **How to apply:** every future brief (implementation milestones included) names its
  verification script/command in the brief itself; no numeric acceptance criterion without
  a producing command.
