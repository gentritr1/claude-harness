- Dawn prebuilt CMake package (v20261002.154047 macos-latest-Release): must `find_package(Threads REQUIRED)` BEFORE `find_package(Dawn)` or configure fails ("Threads::Threads not found"). Target: `dawn::webgpu_dawn`. Real API header is include/dawn/webgpu.h (webgpu/webgpu.h is a 33-line shim).
- emdawnwebgpu local pkg: `--use-port=<pkg>/emdawnwebgpu.port.py` at compile AND link; link with em++ (emcc errors "requires C++").
- Browser WebGPU without Asyncify: request adapter/device with WGPUCallbackMode_AllowSpontaneous in main(), start emscripten_set_main_loop from the device callback. Native: WaitAnyOnly + wgpuInstanceWaitAny (instance needs TimedWaitAny feature).
- Playwright headless WebGPU: default headless-shell = no adapter; + --enable-unsafe-webgpu = SwiftShader whose canvas screenshot is BLANK while page state says drawn (false positive!). Use channel:'chromium' + --enable-unsafe-webgpu → real Metal. Always assert pixels.
- setInputFiles(dir) on webkitdirectory handles the full 1.1 GB install (529 files) in ~1.2 s — paths, not bytes.
- Ghidra export via ExportCorpus is deterministic (2 runs + fresh reanalysis = 0 diffs / 5,618). Full make decomp ≈ 6 min on M1 Pro.
- My own test bug: %.17g prints 0.0066666668280959129 (not the shortest repr) — compare trace strings to what printf emits.
- Pitfall: plan steps in tasks that build a CMake target need EVERY source that target lists to exist by then (main_web.cpp ordering bug caught in self-review).
- Ghidra decompile of GcLegoCamera::Process (37 KB code, M3-critical) fails: at 120 s "process: timeout"; with longer timeout "Response buffer size exceeded" (default 50 MB payload) → DecompileOptions.setMaxPayloadMBytes(1024). Per-function timeouts make output load-dependent (one run lost a 2nd function → decompiled_ok 5616, member_access −432): default 300 s + one 4x retry. Ghidra headless exits 0 even when a script fails — scan the log ("REPORT SCRIPT ERROR"/"Script compile failed").
- Validate from a path WITH spaces (repo lives under "Application Support"): first validation at /private/tmp missed .env.local sourcing + make quoting bugs; `normalize()` rewrite dropped trailing '/' → unmount_prefix("lev1/") matched lev10 (caught by existing test).
- Determinism claims need ≥3 runs: ParallelDecompiler (work-stealing) export looked identical to sequential in ONE comparison but differs in 4–9/5,618 functions across full runs (float/double local numbering depends on each worker's prior functions). Fix under test: fixed contiguous chunks, one DecompInterface each.
- Harness trap (2026-10-07): `diff -rq A B | wc -l` printed 0 when A/B didn't exist (script compile failure) → fake "deterministic". Every comparison harness must first assert the outputs exist and the producer logged success.
- Error paths a dev Mac never reaches (2026-10-07): WebGPU "no adapter"/device-failure code had a use-after-free (fail() passed p->error after delete p) that passed every green run because this Mac always has an adapter. Rule: every error path that must "skip"/"exit N" needs a way to be forced natively (LOMN_WEBGPU_BACKEND=d3d12 on macOS → no adapter) + an ASan run.
- Reference bundles go stale: M0 fix rounds changed disk_fs.cpp/test_fs.cpp after the M1a-1 REF was cut → plan "cmp == REF" steps became unreachable (Fable caught it). After any fix round on a file a later REF patches, re-run `git apply --check` AND re-derive the plan's cmp/case-count expectations.
- Research scripts committed with an absolute home-dir path (username) — fixed in 9c3ad84 (read LOMN_DATA), but the path is still in git history: squash/rewrite before the repo goes public. Pre-commit habit: `git grep -n /Users/`.
- mutate.py-style harnesses that symlink `os.path.join(W, ".toolchain")` with W="." create a self-referencing relative symlink → every mutant "MISSED" (build fails, not test). Always abspath harness roots.
- Fake RED (2026-10-07, M0 Task 10 B2): implementer's "RED" for a json_escape change was only the new header's missing-file compile error; the helper was unit-tested but loop.cpp escaped 1 of 2 strings (an edit-script substitution missed a line break) and the report claimed both. Detection rule: RED must be a failing assertion on the behaviour at the call site (the metrics.json writer), not a build error or a helper test. Brief rule: "test through the writer/integration point" for any fix applied at call sites.
- Controller verification pattern that kept paying off in M0: archive the commit (`git archive <sha> | tar -x`) into the scratchpad, symlink .toolchain/.venv/.env.local/gen/web/node_modules, run `make -o .venv/.ok check` (the -o is needed: a symlinked .venv looks stale to make), plus revert-the-fix RED builds. Caught 3 real defects that green implementer runs hid.
- Real-data oracles are blind to hostile-input DoS (M1a-1, 2026-10-07): parsers passing 39/39 oracles, ASan on the full install and 10/10 mutations still had two quadratic paths (BLK unterminated-name runs: 672 KB file aborts wasm32's 2 GB; .x material×member: 880 KB → 4.8 s). Found only by an opus reviewer told to fuzz natively AND as wasm32 (32-bit size_t, 2 GB cap) with crafted worst cases. Rule: every untrusted-format parser review includes (a) a sanitizer mutation fuzz on both targets, (b) a crafted-input time/memory probe per loop over attacker-controlled counts; caps are set from MEASURED real-data maxima (here 2 B run / 5,489 objects / 2.5 MB entry → caps 512 / 131072 / 64 MiB).
- §6 red flag fired again (2026-10-07, M1a-2 plan): a heredoc `python3 - <<EOF … assert … EOF` followed by `git add … && git commit` on the next line — the assertion failed, the commit still ran (newline ≠ &&), committing the plan without the edit (9409a8d; fixed in 8d16f4e). Rule: any multi-step edit+commit Bash call starts with `set -e`, or commit in its own call after reading the edit's result.
- zsh word-splitting trap fired twice (diff -rq loop, then `for a in "lev1 vllg"…; set -- $a`): zsh does NOT split unquoted $var. Use `pair=lev1:vllg; ${pair%%:*}` / `${pair##*:}` instead.
- GPU pixel determinism (M1a-2 REF2): same Metal render differed in 2 pixels at an alpha-tested edge in 1 of ≥17 runs. Real-scene PNG compares need a tolerance (≤16 px, ≤8 levels); null-backend logs stay byte-exact.
- Render-state tests must be able to fail (M1a-2 T2 review): the GPU depth test drew far-then-near, so Less/LessEqual/Always/disabled all passed. Rule: every pinned render state needs a case whose expected pixel differs under the flipped state (near-first for depth compare; depth_write=false), plus a mutation that flips it.
- Process audit 2026-10-07 (harness-audit, 2,554 calls, 117 failures, ≈1.5 h lost): top causes zsh `=`-expansion (29 — an unquoted word starting with `=`, e.g. `== $f`, is a command lookup in zsh: always quote such strings) and early toolchain timeouts (28). Subagent "parked on coordinator" 3.1 h is fix-round resumption, by design. Below §10 experiment threshold — no route change.
- "Same bits, different print" can hide a sign bug (M1a-3 T3, 2026-10-07): C++ OSI reader printed 4294565113 vs Python -402183 for the vllg fog colour; implementer AND controller accepted it as representation. Opus review compared all 8,406 methods: a `cond ? int32_t(x) : uint32_t` ternary decays to uint32_t → every negative i32 literal wrong (INT_MIN/-1 folded to 0.5). Rule: a numeric cross-check mismatch is a defect until traced through every downstream use (fold arithmetic, not just colour bits); compare ALL entries, not one; unit tests must not cast through the same type as the bug.
- Oracles share transcribed constants (M1a-3 T5): REF3 and its "independent" A9 oracle both byte-swapped the SortIt FourCC ids (exe bytes "1yks"/"rtaw" are LE sky1/watr) — builder even noted they "never match" and Fable accepted it; 9/123 areas mis-ordered, invisible to every test (3-area oracle run, synthetic scene without those ids). Opus reviewer found it by sweeping the oracle over ALL 123 areas (96 agree) and reading the exe bytes. Rules: (1) an oracle is independent only where it re-derives — any constant/table it transcribes from the implementation is a shared-failure point, cite it from the binary separately; (2) run oracles over the FULL real corpus at least once per milestone, not a sample; (3) a "never matches" constant is a red flag — check byte order.

- 2026-10-07 M1a-4 T4 review: oracle and shim both modelled SetCaveLighting(0x0048e670) as "×0.25 on true, no-op on false"; decomp shows SetIntensity OVERWRITE on both branches (29/123 areas potentially affected) yet a9-sweep was 123/123. - 2026-10-07 M1a-4 T4 re-review N-1: on a clean tree `make check` runs pytest (test-tools) before the native build, so tests needing build/native SKIP silently (75 passed 4 skipped vs 79 passed with a warm build) — the green result depended on build order. - 2026-10-07 ~19:58: the main checkout's web/node_modules — the symlink target of EVERY scratch copy/worktree shim — was emptied by an unidentified process (likely a cleanup through a copy's symlinked path, e.g. `rm -rf copy/web/node_modules/` with a trailing slash follows the link). - 2026-10-07 19:36: self-referencing symlinks `.toolchain/.toolchain` and `gen/gen` appeared in the main checkout (same window as the web/node_modules wipe at 19:58). Cause: a shim setup `ln -s "$R/x" "$d/x"` run where `$d/x` already existed as a dir or link (or `$d` == the main checkout) — `ln -s` then creates the link INSIDE the target. Fix: unlink (never rm -r) the inner link. Rule for every shim helper: use `ln -sfn`, and refuse when the copy dir equals the main checkout.
